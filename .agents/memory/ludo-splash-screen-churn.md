description: SplashScreen.tsx gets replaced wholesale on each new creative brief, not incrementally edited. Know this going in.
---

`artifacts/ludo-dz/src/components/SplashScreen.tsx` has already been through multiple *complete* visual-concept rewrites, not incremental tweaks: "Midnight Royale" (rotating gold zellige jewel-cage, orbiting gem loading indicator, sparkle/dust/light-trail atmosphere) → "The Ludo Eclipse" (2026-08-04: static polished-gold "solar eclipse" bezel, breathing multicolour aurora, frosted-glass neon corner pawns, wave-animated colour-cycling loading dots) → "Destiny Die" (2026-08-05: a true CSS 3D tumbling die — `perspective` + `transformStyle:"preserve-3d"` + 6 `rotateX/Y(±90/180) translateZ(half)` faces, animated via `useAnimationControls` with a one-shot dramatic tumble that hands off to an infinite slow `rotateY` showcase spin — replacing all bezel/ring/pawn iconography with the die itself as the hero object, plus minimal glowing corner brackets instead of literal pawn sprites).

**CSS 3D confirmed viable in this stack:** the "Destiny Die" tumble was verified via live `Screenshot(appPreview)` to render genuine perspective foreshortening (two faces meeting at a visibly receding edge, not a flat card doing a 2D spin) — `perspective`/`preserve-3d`/`rotateX`/`rotateY` as Framer Motion `style` props compose correctly in this project's React+Vite+Framer Motion setup. Safe to reuse this technique for future hero-object animations in this file; avoid combining `backdropFilter` with the rotating 3D faces themselves (cross-browser blur+3D-transform quirks) — reserve glass/blur effects for flat 2D layers.

**Screenshot-timing quirk for mount-triggered animations:** repeated `Screenshot(appPreview)` calls against a component whose animation timeline starts at mount (like this splash, auto-hidden after a fixed `setTimeout` in `App.tsx`) land at roughly the same early instant each time (~0.5-0.8s post-mount here) because each call is a fresh page load with fairly consistent load+capture overhead — good for verifying entrance choreography, unreliable for sampling later/idle animation states unless the display duration is temporarily extended.

**Why:** the user briefs this screen as a named creative concept ("NEW VISUAL CONCEPT: THE LUDO ECLIPSE...") with an explicit instruction to discard the previous code logic, not merge with it. Each brief so far has specified its own centrepiece animation metaphor (spinning ring vs. static bezel + breathing glow), its own loading-indicator mechanic, and which older decorative layers to drop (sparkles/dust/light-trails/rotating jewel-cage were all removed, not restyled).

**How to apply:** when asked for a new splash-screen "concept," don't try to preserve the prior file's component structure or decorative systems by default — re-read the brief's numbered constraints line by line and rewrite fresh, keeping only what it explicitly says to retain (typically: the deep blue/emerald background hue journey, the four corner player pawns, the exact "LUDO DZ" title treatment/font, and the bilingual FR/AR subtitle+loading text with their existing `textTransform:uppercase` CSS — the brief's literal all-caps text like "LE LUDO ALGÉRIEN" is just how those already-uppercase-transformed strings render, not a request to change casing logic or drop Arabic support). The component's external contract (`SplashScreen({ lang: "fr" | "ar" })`, single default export) has stayed stable across rewrites — only the internal implementation churns.
